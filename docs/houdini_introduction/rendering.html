マテリアルとレンダリング

この章では、はじめてのモデリング で作った机に質感を付け、ライトとカメラを置いて、Houdini に付属するレンダラー Karma で画像を作る。Houdini でレンダリングのためのシーンを組む環境を Solaris と呼ぶ。Solaris は、USD という形式でシーンを表す。

USD と Solaris

USD（Universal Scene Description）は、3DCG のシーン全体（形状、マテリアル、ライト、カメラ、それらの配置）を記述するための形式である。もとは映画制作会社の Pixar が開発し、現在は OpenUSD としてオープンソースで公開されている。多くの 3DCG ソフトウェアが対応していて、異なるソフトウェアの間でシーンを受け渡すのに使われる。

USD のシーンをステージ（stage）と呼ぶ。ステージは、プリム（prim）と呼ばれる要素の木構造である。各プリムは /table や /materials/wood のようなパスを持つ。ファイルシステムのディレクトリとファイルに似ている。

Solaris では、LOP（/stage のネットワーク）のノードをつないでステージを組み立てる。SOP のノードがジオメトリを受け取って加工するのと同じように、LOP のノードはステージを受け取って、プリムを追加したり変更したりする。ステージの木構造は、Scene Graph Tree というペインで確かめられる。

Houdini には、LOP の作業に向いた画面の配置が用意されている。メインメニューのバーにある最初のドロップダウンメニュー（デスクトップの切り替え。既定では Build と表示されている）で Solaris を選ぶと切り替わる。

Karma

Karma は、Houdini に付属するレンダラーで、3DCG の基礎知識 で説明したレイトレーシングで画像を計算する。CPU で計算する Karma CPU と、CPU と GPU の両方を使える Karma XPU がある。本資料では Karma CPU を使う。

Solaris のビューポートでは、上部のメニューで表示に使うレンダラーを選べる。Karma CPU を選ぶと、ビューポートの中でレンダリングの結果を確かめながら作業できる。最初はざらついた画像が表示され、時間とともに滑らかになる。

マテリアル

Karma のマテリアルは、MaterialX という形式で定義するのが標準である。MaterialX も、異なるソフトウェアの間でマテリアルを受け渡すために作られたオープンな形式である。

MtlX Standard Surface ノードは、多くの質感を 1 個のノードで表せる汎用のマテリアルである。主なパラメーターは次のとおりである。

作例: 机をレンダリングする

はじめてのモデリング で作った /obj/table を読み込み、床と一緒にレンダリングする。ネットワークは 図 21 のとおりである。サンプルコードの build_render.py でも同じネットワークを作れる。

シーンを読み込む

ネットワークエディターで /stage を開き、次のノードを作る。

  1. SOP Import（table）: SOP Path を /obj/table/OUT、Primitive Path を /table にする。机の形状が、ステージの /table に読み込まれる。

  2. SOP Create（floor）: Primitive Path を /floor にする。ノードをダブルクリックして中に入ると SOP のネットワークになっているので、Grid ノードを作り、Size を 6、6 にして Display フラグを立てる。U で /stage に戻る。

  3. Merge（merge）: table と floor をつなぐ。

マテリアルを割り当てる

  1. Material Library（materials）: merge をつなぐ。ダブルクリックして中に入り、MtlX Standard Surface ノードを 2 個作る。名前を wood と floor_mat にする。

    • wood: Base タブの Color を 0.45、0.28、0.15（茶色）、Specular タブの Roughness を 0.4 にする。

    • floor_mat: Color を 0.6、0.6、0.6（灰色）、Roughness を 0.8 にする。

  2. U で /stage に戻り、materials のパラメーターを設定する。Number of Materials を 2 にし、それぞれの行を次のように設定する。

    表 30 Material Library の設定

    Material VOP

    Material Path

    wood

    /table

    1 列目の Material VOP は Material Library の中のノードの名前、2 列目の Material Path はステージの中のマテリアルのパスである。Assign to Geometry をオンにすると、Geometry Path のプリムにそのマテリアルが割り当てられる。

カメラとライトを置く

  1. Camera（camera）: Primitive Path を /cameras/camera にする。Translate を 3.2、2.4、3.8 にし、Enable Look At をオンにして、Look At Position を 0、0.4、0 にする。カメラが、机の中心の少し上を向く。

  2. Dome Light（dome_light）: Intensity を 0.6 にする。空全体からの柔らかい光で、影の部分も真っ暗にならない。

  3. Distant Light（sun）: Rotate を -50、30、0、Intensity を 2 にする。斜め上から差す平行な光で、はっきりした影を作る。

ライトとカメラも、ステージの中のプリム（/lights/sun など）として追加される。

レンダリングする

  1. Karma Render Settings（render_settings）: 次のパラメーターを設定する。

    • Camera: /cameras/camera

    • Resolution: 横を 1280 にする。縦は、カメラの縦横比（既定では 16:9）から自動的に 720 になる。

    • Output Picture: $HIP/render/table.jpg

    • Path Traced Samples: 32（1 ピクセルあたりの光線の本数に関係する値。大きいほどノイズが減り、時間がかかる）

  2. USD Render ROP（render）: render_settings をつなぎ、Render to Disk を押す。

レンダリングが終わると、hip ファイルを保存したディレクトリの render ディレクトリに table.jpg ができる。hip ファイルを保存する前は、$HIP が Houdini を起動したときの作業ディレクトリなどを指すため、先に hip ファイルを保存しておく。本資料の環境では、レンダリングに約 1 分かかった。

Apprentice では、レンダリングした画像の右下に Houdini のロゴ（透かし）が入る。解像度は 1920 x 1080 までである。

build_render.py を hython で実行した場合は、ネットワークを組み立ててステージのプリムの一覧を表示する。画像も書き出すには、main() の後で hou.node("/stage/render").render() を実行する。

レンダリングの品質と時間

レンダリングの時間は、主に解像度と光線の本数で決まる。作業中は解像度を下げ、Path Traced Samples を小さくして素早く確かめ、最後に値を上げて仕上げる。画像にざらつき（ノイズ）が残る場合は Path Traced Samples を上げる。
