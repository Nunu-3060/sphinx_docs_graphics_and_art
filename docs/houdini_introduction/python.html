Python による操作

Houdini は Python で操作できる。画面で行うほとんどの操作（ノードの作成、接続、パラメーターの設定、ファイルの保存など）を、Python のコードで行える。この章では、Houdini の Python API である hou モジュールの使い方と、Python を使う 4 つの場面（Python Shell、Python SOP、シェルフツール、hython）を説明する。

hou モジュール

Houdini の Python API は、hou という名前のモジュールで提供されている。HOM（Houdini Object Model）とも呼ぶ。Houdini 22.0 には Python 3.13 が付属していて、Houdini の中で動く Python のコードは、全てこの Python で実行される。

Houdini の中の Python Shell やパラメーターの式では、hou は最初から読み込まれている。自分で作ったモジュール（ファイル）の中では、import hou と書く。

表 27 hou モジュールの主なクラスと関数

クラス、関数

内容

hou.node(パス)

パスを指定してノードを取得する。見つからなければ None を返す。

hou.Node

ノード。createNode()、setInput()、parm()、children() などのメソッドを持つ。SOP のノードは hou.SopNode で、geometry() で出力のジオメトリを取得できる。

hou.Parm、hou.ParmTuple

パラメーター、パラメーターのタプル。eval() で値を読み、set() で値を書く。setExpression() で式を設定する。

hou.Geometry

ジオメトリ。points()、prims()、pointAttribs() などで中身を読む。

hou.Point、hou.Prim、hou.Vertex

ポイント、プリミティブ、バーテックス。attribValue() でアトリビュートの値を読む。

hou.hipFile

hip ファイルの保存（save()）と読み込み（load()）。

hou.frame()、hou.setFrame()

現在のフレームの取得と変更。

全てのクラスと関数は、ヘルプの HOM のリファレンスで調べられる。

Python Shell で試す

Windows ‣ Python Shell で Python Shell を開き、次のコードを 1 行ずつ入力する。

1geo = hou.node("/obj").createNode("geo", "hello")
2box = geo.createNode("box")
3box.parmTuple("size").set((2, 1, 1))
4xform = geo.createNode("xform")
5xform.setFirstInput(box)
6xform.parm("ry").set(45)
7xform.setDisplayFlag(True)
8print(len(xform.geometry().points()))
9print([n.name() for n in geo.children()])

1 行目で /obj に Geometry ノード hello を作り、2 行目でその中に Box ノードを作っている。createNode() の 1 番目の引数はノードの種類の内部名、2 番目の引数はノードの名前である。名前を省略すると、box1 のような名前が自動的に付く。4 行目の "xform" は Transform ノードの内部名である。ノードの種類の内部名は、Tab メニューでノードを作った後に、Python Shell で hou.node("ノードのパス").type().name() を実行すると確かめられる。

8 行目は、Transform ノードの出力のポイントの数（8）を表示する。9 行目は ['box1', 'transform1'] を表示する。ネットワークエディターで /obj/hello を開くと、2 個のノードがつながっていることを確かめられる。

画面で操作したことをコードで書くときは、次の方法で必要な名前を調べる。

  • パラメーターの内部名: パラメーターのラベルにマウスを重ねる。

  • メニューの値: Python Shell で node.parm("名前").parmTemplate().menuItems() を実行すると、メニューの選択肢の内部名が分かる。

スクリプトでネットワークを組む

本資料のサンプルコードの build_*.py は、全てこの方法でネットワークを組み立てている。例えば build_table.py の、天板を作る部分は次のとおりである。

 1def build() -> hou.Node:
 2    """/obj/table に机のネットワークを作り、出力の Null ノードを返す。"""
 3    geo = recreate_geo("table")
 4    top_w, top_t, top_d = TOP_SIZE
 5    leg_h = TABLE_HEIGHT - top_t
 6
 7    # 天板: 箱を作り、脚の上に載る高さまで持ち上げる。
 8    top = geo.createNode("box", "top")
 9    top.parmTuple("size").set(TOP_SIZE)
10    lift = geo.createNode("xform", "lift_top")
11    lift.setFirstInput(top)
12    lift.parm("ty").set(leg_h + top_t / 2)
13
14    # 天板の角を丸める。
15    bevel = geo.createNode("polybevel::3.0", "bevel_top")
16    bevel.setFirstInput(lift)
17    bevel.parm("offset").set(0.005)
18

recreate_geo() は、examples/common.py で定義した関数で、同じ名前のノードがあれば削除してから Geometry ノードを作る。こうしておくと、スクリプトを何度実行しても同じ結果になる。

"polybevel::3.0" の ::3.0 は、ノードの種類のバージョンである。Houdini では、ノードの仕様を大きく変えるときに、古いバージョンを残したまま新しいバージョンを追加する。Tab メニューで作っても、createNode("polybevel") のようにバージョンを省略しても、その時点の最新のバージョンが作られる。ただし、Houdini を更新して新しいバージョンが追加されると、同じスクリプトから別のバージョンのノードが作られ、パラメーターの名前が変わることがある。本資料のスクリプトでは、結果を再現できるようにバージョンを明示している。ノードのバージョンは、Python Shell で node.type().name() を実行すると分かる。

スクリプトでネットワークを組む利点は、次のとおりである。

  • 手順が正確に記録され、同じものを何度でも作れる。

  • Git などのバージョン管理システムで差分を確認できる。hip ファイルはバイナリなので差分が読めない。

  • パラメーターを変えたバリエーションを、ループで大量に作れる。

ジオメトリを読む

hou.Geometry を使うと、ノードの出力の中身を Python で調べられる。サンプルコードの inspect_geometry.py は、ジオメトリの要素の数、アトリビュートの一覧、先頭のポイントの位置を表示する。

 1def describe(node_path: str, max_points: int = 5) -> None:
 2    """node_path のノードが出力するジオメトリの要素数、アトリビュート、先頭のポイントを表示する。"""
 3    node = hou.node(node_path)
 4    if node is None:
 5        raise ValueError(f"ノードが見つからない: {node_path}")
 6    geo = node.geometry()
 7
 8    print(f"== {node.path()} ({node.type().name()}) ==")
 9    print(f"ポイント: {len(geo.points())}, プリミティブ: {len(geo.prims())}, "
10          f"バーテックス: {geo.intrinsicValue('vertexcount')}")
11
12    # アトリビュートを、所属する階層（クラス）ごとに表示する。
13    for label, attribs in (("ポイント", geo.pointAttribs()),
14                           ("バーテックス", geo.vertexAttribs()),
15                           ("プリミティブ", geo.primAttribs()),
16                           ("ディテール", geo.globalAttribs())):
17        names = ", ".join(f"{a.name()}({a.dataType().name()}x{a.size()})" for a in attribs)
18        print(f"{label}アトリビュート: {names or 'なし'}")
19
20    # 先頭のポイントの位置を表示する。
21    for point in geo.points()[:max_points]:
22        x, y, z = point.position()
23        print(f"  ポイント {point.number()}: P = ({x:.3f}, {y:.3f}, {z:.3f})")

 5プリミティブアトリビュート: なし

Python SOP

Python SOP は、Python のコードでジオメトリを作ったり変更したりする SOP である。Python Code パラメーターに書いたコードが、ノードがクックされるたびに実行される。コードの中では、hou.pwd() がこの Python SOP 自身を表し、hou.pwd().geometry() が出力するジオメトリを表す。入力がつながっていれば、出力のジオメトリは最初は入力のコピーであり、それを変更する。入力が無ければ空のジオメトリから始まる。

サンプルコードの python_sop_wave.py は、ポイントとポリゴンを作って波打つ面を作る。

 1"""Python SOP に貼り付けて使うコード。波打つ面をポイントとポリゴンから作る。
 2
 3build_python_sop.py が、このファイルの中身を Python SOP の Python Code
 4パラメーターに設定する。Python SOP の中では、hou.pwd() がその Python SOP
 5自身を表す。
 6"""
 7
 8from __future__ import annotations
 9
10import math
11
12import hou
13
14COLUMNS = 40      # x 方向のポイント数
15ROWS = 40         # z 方向のポイント数
16SIZE = 4.0        # 面の一辺の長さ
17AMPLITUDE = 0.2   # 波の高さ
18
19node = hou.pwd()
20geo = node.geometry()       # このノードが出力するジオメトリ（最初は空）
21phase = hou.frame() * 0.1   # フレームが進むと波が動く
22
23# ポイントを作る。i が z 方向、j が x 方向の番号である。
24positions = []
25for i in range(ROWS):
26    for j in range(COLUMNS):
27        x = (j / (COLUMNS - 1) - 0.5) * SIZE
28        z = (i / (ROWS - 1) - 0.5) * SIZE
29        y = AMPLITUDE * math.sin(3.0 * x + phase) * math.cos(2.0 * z)
30        positions.append(hou.Vector3(x, y, z))
31points = geo.createPoints(positions)
32
33# 隣り合う 4 つのポイントを結んで四角形のポリゴンを作る。Houdini では、
34# 表から見て時計回りにポイントを並べると、その面が表（法線の向き）になる。
35quads = []
36for i in range(ROWS - 1):
37    for j in range(COLUMNS - 1):
38        a = i * COLUMNS + j
39        quads.append((points[a], points[a + 1], points[a + COLUMNS + 1], points[a + COLUMNS]))
40geo.createPolygons(quads)

createPoints() は、位置のリストからまとめてポイントを作り、作ったポイントのリストを返す。createPolygons() は、ポイントの組のリストからまとめてポリゴンを作る。3DCG の基礎知識 で説明したとおり、Houdini では面を表から見て時計回りにポイントを並べる。逆に並べると、面が下を向いてしまう。

このコードを Python SOP に貼り付けるには、build_python_sop.py を実行するか、Python SOP を作って Python Code にファイルの中身を貼り付ける。hou.frame() を使っているので、再生すると波が動く。

VEX 入門 で見たとおり、Python SOP は要素の多い処理では VEX よりずっと遅い。Python SOP は、ファイルや外部のライブラリからデータを読み込んでジオメトリにする場合など、Python でなければ書けない処理に使う。

シェルフツール

シェルフツールは、シェルフに置くボタンで、押すと Python のスクリプトが実行される。よく行う操作を 1 回のクリックで実行できるようにする。

  1. シェルフのタブの空いている所で RMB をクリックし、New Tool を選ぶ。

  2. 開いたウィンドウの Options タブで、Name（内部名）と Label（表示名）を入力する。

  3. Script タブに Python のコードを書き、Accept を押す。

サンプルコードの shelf_tool_add_out.py は、選択している SOP のノードの後ろに、出力用の Null ノード OUT を追加するツールである。ファイルの中身を Script タブにそのまま貼り付けて使う。

 1"""シェルフツールの例: 選択した SOP ノードの後ろに、出力用の Null ノードを追加する。
 2
 3シェルフツールの Script タブに、このファイルの中身をそのまま貼り付けて使う。
 4貼り付けた場合は、最後の行で add_out_nulls() が実行される。
 5"""
 6
 7from __future__ import annotations
 8
 9import hou
10
11
12def add_out_nulls() -> list[hou.Node]:
13    """選択中の SOP ノードそれぞれの後ろに OUT という Null ノードを作り、表示する。"""
14    created = []
15    for node in hou.selectedNodes():
16        if node.type().category() != hou.sopNodeTypeCategory():
17            continue    # SOP 以外のノードは対象外
18        null = node.parent().createNode("null", "OUT")   # 名前が重なると OUT1 などになる
19        null.setFirstInput(node)
20        null.moveToGoodPosition()
21        null.setDisplayFlag(True)
22        null.setRenderFlag(True)
23        created.append(null)
24    if not created:
25        hou.ui.displayMessage("SOP ノードを選択してから実行する。")
26    return created
27
28
29add_out_nulls()

hou.selectedNodes() は、ネットワークエディターで選択しているノードのリストを返す。hou.ui.displayMessage() は、メッセージのウィンドウを表示する。hou.ui は画面に関する機能なので、画面の無い hython では使えない。

hython

hython は、Houdini に付属する Python のインタープリターで、hou モジュールを最初から使える。Houdini の画面を開かずに、hip ファイルの読み込み、ノードのクック、ファイルの書き出し、レンダリングなどを実行できる。大量のファイルを一括で処理したり、夜間に自動でレンダリングしたりするのに使う。

hython の実行ファイルは、Houdini のインストール先の bin ディレクトリにある。

1"C:\Program Files\Side Effects Software\Houdini 22.0.466\bin\hython.exe" build_city.py city.hipnc

本資料のサンプルコードの build_*.py は、hython で実行すると、ネットワークを組み立ててエラーが無いかを確かめ、結果の一部を表示する。コマンドライン引数でファイル名を渡すと、シーンを hip ファイルに保存する。この部分は、各スクリプトの main() 関数に書いてある。

hython は、Apprentice のライセンスでも動作する（本資料の執筆時に確認した）。ただし、保存されるファイルは Apprentice の形式（非商用）になる。

型ヒントと静的検査

hou モジュールは Houdini の中でしか読み込めず、型の情報（スタブ）も付属していない。そのため、Houdini の外で mypy などの型検査を実行すると、hou を読み込めないというエラーになる。本資料のサンプルコードでは、examples/setup.cfg に次の設定を書き、hou に関する値を Any 型として扱わせている。

 1[flake8]
 2max-line-length = 120
 3exclude = __pycache__
 4
 5[mypy]
 6strict = True
 7
 8# The hou module can only be imported inside Houdini and has no type stubs.
 9# Values from hou are treated as Any.
10# (Keep this file ASCII only: mypy reads it with the locale encoding.)
11[mypy-hou]
12ignore_missing_imports = True

この設定で、hou 以外の部分（自分で書いた関数の引数や戻り値）は厳密に型検査される。setup.cfg に日本語のコメントを書くと、Windows では mypy が設定ファイルを読めずにエラーになるため、英語で書いている。

モジュールの名前に注意する

自分で作った Python のファイルの名前が、Houdini が内部で使うモジュールの名前と同じだと、Houdini がそちらを誤って読み込むことがある。Python は、実行したスクリプトのあるディレクトリや sys.path に追加したディレクトリから、先にモジュールを探すためである。

本資料の執筆中にも、hython で試験用に作った dbg.py が Houdini の内部のモジュール dbg の代わりに読み込まれ、マテリアルの変換が黙って失敗して、レンダリング結果から色が消える現象が起きた。エラーの表示はほとんど無かった。自分のファイルには、build_table.py のように用途の分かる、他と重なりにくい名前を付けるとよい。
