VEX 入門

VEX は、Houdini の中でジオメトリやボリュームを処理するための言語である。文法は C 言語に似ている。VEX のコードは、ポイントやプリミティブの 1 個 1 個に対して並列に実行される。そのため、大量の要素を高速に処理できる。この章では、Attribute Wrangle ノードで VEX を使う方法を説明する。

Attribute Wrangle

Attribute Wrangle ノードは、VEXpression パラメーターに書いた VEX のコードを、入力のジオメトリの要素ごとに実行するノードである。コードを実行する要素の種類は、Run Over パラメーターで選ぶ。

表 21 Run Over の選択肢

選択肢

コードを実行する回数と単位

Points（既定）

ポイントごとに 1 回ずつ

Primitives

プリミティブごとに 1 回ずつ

Vertices

バーテックスごとに 1 回ずつ

Detail (only once)

ジオメトリ全体に対して 1 回だけ。入力が無くても実行される。

Numbers

指定した回数

例えば、Grid ノードの後ろに Attribute Wrangle ノードをつなぎ、VEXpression に次の 1 行を書く。

1@P.y = sin(@P.x * 2.0) * 0.3;

Run Over が Points なので、この行はグリッドの全てのポイントに対して 1 回ずつ実行される。@P は処理中のポイントの位置であり、その y 成分を x 座標の正弦波にしている。結果として、グリッドが波打つ。Python で書くなら次のループに相当するが、VEX ではループを書かない。ループは Houdini が並列に実行する。

1for point in geo.points():
2    pos = point.position()
3    pos[1] = math.sin(pos[0] * 2.0) * 0.3
4    point.setPosition(pos)

基本の文法

VEX の文法は C 言語に近い。

  • 文の終わりにはセミコロン（;）が必要である。

  • コメントは // から行末まで、または /* と */ の間である。

  • 変数は、型を付けて宣言する。int count = 10; のように書く。

  • if、for、while、foreach などの制御文を使える。

  • 三角関数の角度はラジアンで指定する。

ベクトルの成分は、v.x、v.y、v.z で読み書きする。色として使うときは v.r、v.g、v.b とも書ける。

ベクトルを作るには 2 つの書き方がある。

1vector a = {1, 0, 0};          // 波かっこ: 定数だけ書ける
2float h = 2.0;
3vector b = set(0, h, 0);       // set(): 変数や式を書ける
4// vector c = {0, h, 0};       // エラーになる

波かっこ（{}）の中には定数しか書けない。変数や式を含むベクトルは set() 関数で作る。これは間違えやすい点である。

アトリビュートの読み書き

@ の後にアトリビュートの名前を書くと、処理中の要素のアトリビュートを読み書きできる。存在しないアトリビュートに書き込むと、新しく作られる。

@ の前に 1 文字を付けて、アトリビュートの型を指定する。

表 23 アトリビュートの型の指定

4@name

型を省略すると float とみなされる。ただし、P、N、Cd、v、uv、scale などの決まったアトリビュートは、型を省略してもベクトルとして扱われる。id は整数、name は文字列として扱われる。自分で作るアトリビュートには、型を明示する習慣を付けるとよい。@height と書いたつもりで height をベクトルとして作ってしまう、といった間違いを防げる。

パラメーターを読む

コードの中の定数を後から調整できるように、パラメーターにしておくと便利である。VEX では chf("名前")（浮動小数点数）、chi("名前")（整数）、chv("名前")（ベクトル）、chramp("名前", 位置)（ランプ）で、ノードのパラメーターを読める。

chf("amplitude") のように書いた後、VEXpression の右にあるボタン（ツールチップは「Creates spare parameters for each unique call of ch()」）を押すと、コードの中の ch 系の関数の呼び出しに対応するパラメーターが、ノードに自動的に追加される。このように後から追加したパラメーターを、スペアパラメーターと呼ぶ。

よく使う関数

VEX には多くの関数が用意されている。よく使うものを挙げる。全ての関数は、ヘルプの VEX の関数の一覧で調べられる。

関数の最初の引数の数字（input）は、ノードの入力の番号である。0 が 1 番目の入力、1 が 2 番目の入力を表す。addpoint などのジオメトリを変更する関数の 0 は、このノードが出力するジオメトリを表す。

入力のジオメトリと出力のジオメトリ

VEX のコードは、全ての要素で同時に（並列に）実行される。そのため、コードの中では次の 2 つを区別する必要がある。

  • point(0, "P", n) のような関数が読むのは、ノードに入力された（変更される前の）ジオメトリである。他の要素がコードの中で書き換えた値は読めない。

  • @P = ... や setpointattrib() で書いた値と、addpoint() で追加したポイントは、全ての要素の処理が終わった後で出力のジオメトリに反映される。

この仕組みにより、要素の処理の順序を気にせずにコードを書ける。逆に、「隣のポイントを先に動かし、その結果を使って自分を動かす」ような逐次的な処理は、1 個の Wrangle では書けない。その場合は Wrangle を 2 個に分けるか、Detail (only once) で全ての要素をループで処理する。

作例

サンプルコードの build_vex_examples.py は、/obj/vex_examples の中に次の 4 つの例を作る。VEX のコードは examples/vex ディレクトリにあり、Attribute Wrangle の VEXpression にそのまま貼り付けて使える。各コードの ch 系の関数が読むパラメーターは、前述のボタンで作る。スクリプトで作った場合は、スペアパラメーターも作られる。

例 1: 波打つグリッド

Run Over は Points である。@Time を使っているので、再生すると波が流れる。

1// グリッドを波打たせる（Run Over: Points）。
2// @Time は秒単位の現在時刻なので、再生すると波が流れる。
3float freq = chf("frequency");   // 波の細かさ
4float amp = chf("amplitude");    // 波の高さ
5@P.y = sin(@P.x * freq + @Time * 2.0) * amp;

例 2: でこぼこの球

Run Over は Points である。法線 @N の向きに、ノイズの値だけポイントを動かす。入力の球には、Normal ノードで法線を付けておく。

1// 球の表面を法線の方向にでこぼこさせる（Run Over: Points）。
2float n = noise(@P * chf("frequency"));   // 0 から 1 程度の滑らかな乱数
3@P += @N * (n - 0.5) * chf("amplitude");
4@Cd = set(n, n, 1.0);                     // でこぼこの量を色でも確認する

例 3: らせんを描く

Run Over は Detail (only once) で、入力は無い。addprim でポリライン（折れ線）のプリミティブを 1 個作り、for ループで作ったポイントを addvertex で順につないでいく。PI は円周率を表す定数である。

 1// ポイントとポリラインを作ってらせんを描く（Run Over: Detail）。
 2int count = chi("count");        // ポイントの数
 3float turns = chf("turns");      // 巻き数
 4float height = chf("height");    // らせんの高さ
 5
 6int prim = addprim(0, "polyline");
 7for (int i = 0; i < count; i++) {
 8    float t = float(i) / (count - 1);        // 0 から 1
 9    float angle = t * turns * 2.0 * PI;      // ラジアン
10    vector pos = set(cos(angle), t * height, sin(angle));
11    int pt = addpoint(0, pos);
12    addvertex(0, prim, pt);                  // ポイントをポリラインに繋ぐ
13}

例 4: 最も近いポイントまでの距離で色を付ける

Run Over は Points である。1 番目の入力にグリッドを、2 番目の入力に例 3 のらせんをつなぐ。グリッドの各ポイントについて、らせんの最も近いポイントを nearpoint(1, @P) で探し、その距離で色を決める。らせんの真下が赤く、離れるほど青くなる。

1// 2 番目の入力（入力番号 1）の最も近いポイントまでの距離で色を付ける（Run Over: Points）。
2int near = nearpoint(1, @P);                // 最も近いポイントの番号
3vector target = point(1, "P", near);        // そのポイントの位置
4float d = distance(@P, target);
5float t = clamp(d / chf("max_distance"), 0.0, 1.0);
6@Cd = lerp({1.0, 0.3, 0.1}, {0.1, 0.3, 1.0}, t);   // 近いほど赤、遠いほど青

VEX と Python の速さ

VEX は、コンパイルされてから、CPU の複数のコアで並列に実行される。Python の Python SOP（Python による操作）でも同じ処理を書けるが、ポイントを 1 個ずつ順に処理するため、ずっと遅い。本資料の環境（16 スレッドの CPU）で、25 万個のポイントを持つグリッドに本章の最初の例と同じ波の計算をしたところ、Attribute Wrangle は約 2 ミリ秒、Python SOP は約 1.8 秒かかった。

要素ごとの計算は VEX で書き、Python はネットワークの操作やファイルの入出力に使うのが基本である。

VOP

VOP は、VEX のプログラムをノードで組み立てる仕組みである。Attribute VOP ノードの中で、sin や noise などの関数を表すノードをつないで処理を作ると、Houdini がそれを VEX のコードに変換して実行する。コードを書くか、ノードをつなぐかの違いで、できることはほぼ同じである。マテリアル（マテリアルとレンダリング）も VOP のネットワークで定義する。
